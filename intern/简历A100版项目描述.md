# 简历 A100 版项目描述

## 基于 nano-vLLM 的 Qwen3.5-9B 多模态推理引擎

- **混合架构与 TP 适配**：区分 8 个 Full Attention 与 24 个 Gated DeltaNet 层，分别管理 Paged KV Cache 与 Conv/Recurrent State Slot；实现 TP=2 张量并行、Variable-length Batched Prefill、Chunked Prefill、Continuous Batching 与双状态池分片；在 2×A100 PCIe 40GB 上完成端到端验证，单 Rank 模型参数由 17.95 GiB 降至 9.41 GiB，GDN State 由 792 MiB 降至 396 MiB，并结合 NCCL 微基准与 Nsight Systems 定位 PCIe AllReduce 通信瓶颈。

- **多模态推理**：支持文本与单图输入，扩展 Processor→Sequence→Packed Prefill 数据链路，根据 Chunk 与 Packed Offset 将 Vision Encoder、Patch Merger 输出回填 Image Placeholder；实现三轴 Interleaved mRoPE、请求级 Visual Embedding Cache 与 Hugging Face Greedy Token 对齐。

- **联合 Prefix Cache 与 BF16 状态压缩**：针对 KV-only 复用导致的 GDN 状态错配，基于链式 Block Hash 与 Token 二次校验匹配最长前缀，联合复用物理 KV 与 GDN Snapshot；采用 FP32 活状态/BF16 快照分级存储及引用计数、容量感知 LRU 管理缓存；A100 TP=2 下复用并跳算 1024-token 前缀，Hot Prefill 由 1165 降至 141 tokens，计算量减少 87.9%。

- **Hybrid CUDA Graph 与性能评测**：构建 B=1/2/4/8/16 Decode Graph Bucket，使用固定地址 Workspace 承载动态 Paged KV Metadata、三轴 Position 与 GDN State Slot，支持 Continuous Batching 下精确路由及非标准 Batch Eager 回退；在 2×A100 PCIe 40GB、TP=2 下实现 3090 次稳定 Graph Replay，Decode 吞吐提升最高 5.53×，B=16 达到 669.72 tok/s、TPOT 约 25.2 ms。

## State-Aware GDN CUDA Kernel 实现与优化

- **问题分析**：Flash Linear Attention 的连续 Batched State 接口与引擎动态 State Pool 布局不匹配，导致每步 Decode 需要额外执行状态 Gather/Scatter 搬运。

- **融合算子**：使用 `state_slot_ids/gdn_index` 直接寻址 FP32 Recurrent 与 BF16 Conv State Pool，融合状态衰减、Delta Rule、4-tap Causal Conv、SiLU 与原位回写，支持非连续 Tensor Stride。

- **算子优化**：Recurrent 采用 Warp-level Split-K、Warp Shuffle 与 float4 128-bit 访存，Q/K 归一化采用 Warp Shuffle 归约，Conv 采用 BF16×4 向量读写；通过 PyTorch C++/CUDA Extension 接入 Continuous Batching 与 CUDA Graph。

- **性能评测**：在 A100 PCIe 40GB、Qwen3.5-9B 上完成 PyTorch Profiler、CUDA Event 与端到端 Benchmark；自研 State-Aware CUDA 相对 FLA 的完整 Eager Decode 吞吐最高提升 20.51%，B=16 提升 15.45%，并消除每步最高约 5.46 ms 的显式 Gather/Scatter 开销。
